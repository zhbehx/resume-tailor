# 拆 JD：三类要求与隐性信号

## 一、三类要求怎么分

### 硬性要求（不满足就出局）

出现这些词：`必须` `要求` `熟悉/精通` `X 年以上` `本科及以上` `具备…证书`。

处理：逐条对齐证据。做不到时只有两条路——**用相邻经验顶**（“做过 Java 转 Go，3 个月上手两个服务”），或**不投**。不要在简历里假装会。

### 加分项（决定排序，不决定生死）

出现这些词：`优先` `更好` `有…者优先` `了解…加分`。

处理：有就前置到核心成果，没有就完全不提。**空占位的加分项是负分**。

### 隐性要求（决定语气，不写进简历）

| JD 信号 | 通常意味着 | 简历应该怎么变 |
| --- | --- | --- |
| JD 很短（<300 字）、职责写得宽 | 新设岗位 / 团队没定型 | 突出“从 0 到 1、独立推进” |
| 反复强调“抗压、快节奏、能扛” | 加班多、人力紧 | 用“周期/并发”类数字证明产出速度 |
| 要求“跨部门推动、向上沟通” | 协作摩擦是主要痛点 | 写“推动 X 个团队、对齐 N 方”的成果 |
| 薪资区间拉得很宽 | 级别看人定 | 简历里明确体现你想要的级别对应成果 |
| 职责里出现“数据看板、复盘机制” | 团队缺体系 | 写你搭过什么机制、跑过什么会 |
| 强调“对标竞品、快速试错” | 增长压力大 | 写迭代次数、验证周期、失败后调整 |

## 二、从 JD 反推“真正在找的人”

一句话填空，写完给用户确认：

> 这个岗位真正在找的是 **{级别} 的 {职能}，能 {最难的那件事}，并且 {团队现在最缺的那块}**。

例：*“真正在找的是 P6 增长产品，能独立把一条新渠道从 0 跑到月 ROI 打正，并且团队现在缺会做实验设计的人。”*

填完这句话，简历的排序就有了唯一标准：**能证明这半句的内容，全部前置；不能的，删或后置。**

## 三、ATS 与 HR 两道筛

### 机器筛（ATS）

- 用标准标题：`工作经历` `教育背景` `技能`，别用“我的旅程”。
- 不用表格、文本框、分栏、图标代替文字、页眉页脚放关键信息。
- 导出 PDF 后**用鼠标框选文字**，能选中才算过。
- 文件名：`姓名-岗位-年限.pdf`，别用 `简历最终版3.pdf`。

### 人筛（平均 20–40 秒）

- 前 1/3 屏必须出现：级别 + 最强成果 + 与岗位最相关的经历。
- 每段第一行是结论，不是时间地点。
- 数字加粗或独立成句，别埋在长句中部。

## 四、常见 JD 陷阱

| 陷阱 | 真相 | 应对 |
| --- | --- | --- |
| “薪资 15–30K” | 预算按 15 招 | 先问级别再谈薪 |
| “有较强的学习能力” | 没人带，要自驱 | 写自学上手的实例与周期 |
| “熟悉多个方向” | 一人多岗 | 选一个方向做深，其余写“能协作” |
| “结果导向、扁平管理” | 无流程、无支持 | 写你独立定义指标的经历 |
| JD 挂了 3 个月还在招 | 要求不现实或预算不够 | 投但别只投，控制期望 |
